## Key facts

- **Due:** Dec. 11th, 2026, 11:55 PM. The deadline is strict.
- **Submit:** through Brightspace only. Email is not accepted.
- **Package:** one ZIP file named `MBAB5P19_Fall2026_VC-Assign_Group#` (replace `#` with our group number).
- **One file per deliverable** (items 1 to 4 below). Name and label each file and folder clearly.
- **Text format:** MS Word, 1 inch margins, single spacing, 12-point Times New Roman. This does not apply to code, references or appendices.

### 1. Cover page and Table of Contents (3 points)

- A professional cover page: project title, course, group number, group members and other relevant information.
- A detailed TOC that lists every file in the ZIP, including the sections and subsections inside each file.

### 2. Executive Summary (7 points)

Maximum one page. It must cover:

- **Need:** why the application is necessary, and for which users. Use short evidence, for example statistics or industry reports.
- **Purpose:** how the application addresses that need.
- **Content:** the main high-level capabilities. Do not include low-level details.

### 3. Vision and Strategy (60 points)

#### 3.i. What: vision and features (10 points)

- A vision statement of about three sentences that describes the main high-level functions.
- A complete feature list. This is our main planning document.
  - Give each feature a short name and a one-sentence description.
  - Show the menu or page structure, including sub-features.
  - If possible, group the features into the successive "passes" that we will use when we vibe code.

#### 3.ii. How: pictorial description (20 points)

- A series of figures (mock-ups, diagrams) that show how the features will look in the application.
- Show each figure first, then give a short explanation.
- Together, the figures must cover all the features in 3.i. One figure can show many features.
- AI design tools, such as Figma, are permitted.

#### 3.iii. How: vibe coding steps (30 points)

Organise this section by pass. For each pass:

- **In the main text:** the first prompt and all revision prompts, the LLM responses, a screenshot after the first prompt and a screenshot of the final working version.
- **If a pass needs many rounds:** keep the first and last rounds in the main text, and move the other rounds to the appendix.
- **Appendix:** make separate numbered sections and link to them from the main text. Put all the generated code in the appendix. If there is a very large amount of code, put it on a companion site and give the link.

### 4. The application (20 points)

The complete working application, with:

- **User instructions:** login details (a list of test user IDs and passwords is acceptable), user roles, the landing page, the menus, the main sections, and how to save, load, upload and export.
- **The full code as a `.txt` file.**
- **The same code as an `.html` file.** Any user must be able to open it and use all the functions.

The marks are split equally between two criteria:

- **Usability (10):** easy to use and navigate.
- **Comprehensiveness (10):** the functions that a real organisation would expect.

Extra features give extra credit.

### 5. Packaging and professionalism (10 points)

This mark is for the overall quality and presentation of the documents and the application.
